# Version 0.2 override validation

All inputs are synthetic. No provider exports or private account data were used.
The historical schema-1 example and `benchmark.json` remain unchanged.

## Correctness evidence

The full `scripts/verify.py` run passed **97 tests**, including the retained 620
seeded interval/end-to-end cases and **256 new seeded override series** (seeds
710000–710255). The new oracle independently materializes DAILY/WEEKLY originals,
applies explicit changes, measures occupied minute cells, and checks every pair
quadratically. It checks original identities and effective/clipped bounds, including
DATE, floating, UTC, zoned starts, spring gaps, fall folds, changed ends, inherited
durations, transparency, cancellation, EXDATE, duplicates and reordered components.
Focused fixtures cover moved starts across both window edges, exact endpoints,
orphans, conflicting revisions, incompatible values, unknown zones, RANGE,
source-file boundaries, invalid input and resolution exhaustion.

Network-blocked Chromium verifies master/override/occurrence backreferences,
keyboard navigation, filters, cancellation display and hostile text. Existing CLI
collision, signal cancellation, failed-write cleanup and resource tests remain.
A wheel installed in an isolated environment with sockets blocked reproduces both
the historical example (23,400 seconds, 3 pairs) and the override example (9,000
seconds, 3 pairs, one cancellation). Source hashes remain unchanged.

The first oracle run found a **fixture-generation error**: serializing a fold=1
DTEND as local civil time loses the fold bit and creates a nonpositive interval.
The generator now chooses an unambiguous explicit end. The audit correctly rejected
that malformed fixture; this was not treated as a passed run.

## Independent implementation comparison

`compare_recurrence.py` uses **recurring-ical-events 3.8.0**, **python-dateutil
2.9.0.post0**, **icalendar 6.3.2**, and the remaining exact versions recorded in
[recurrence-comparison.json](recurrence-comparison.json). The comparator normalizes
effective starts/ends and explicitly removes CANCELLED/TRANSPARENT reference
components before comparing occupied occurrences. It is a differential check, not
an oracle for all semantics. The full verification command reruns it and compares
the deterministic result to the saved artifact.

Seven fixtures agree: daily/weekly moves from before, within and after the query
window, plus DATE recurrence with an unrelated EXDATE and a resized replacement.
Three differences are preserved, not dismissed or counted as agreements:

| Fixture | Audit | Pinned reference | Interpretation |
| --- | --- | --- | --- |
| Inherited duration | Replacement lasts one hour | Replacement has zero duration | The audit's explicit snapshot policy inherits missing duration; the reference treats missing DTEND as zero. This is a documented policy choice, not a universal interoperability claim. |
| Spring generated gap | Skips March 8 02:30 New York and retains March 11 to satisfy COUNT=4 | Emits the March 8 nonexistent local start as a zero-duration UTC interval, ending the series on March 10 | Audit follows RFC 5545 §3.3.10's skip-without-count rule. The observed reference result is retained as a compatibility discrepancy. |
| Fall elapsed duration | Original November 1 instance remains two elapsed hours | That instance lasts three elapsed hours | Audit follows the exact-duration rule for DTEND-defined recurrence (§3.8.5.3). Reference local arithmetic crosses the fold and changes elapsed duration. |

[RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) and the pinned source review are
linked in [the preimplementation contract](../docs/overrides.md). No upstream
resolution or compatibility with a newer library release is claimed. Inputs are
generated by the comparison script; their hashes and both complete output sets
are retained in JSON. These differences remain limitations when comparing this
tool with another calendar application's interpretation.

The 100 overridden 90-day series retain 8,900 occurrences and occupy 267,000
seconds. The dense replacement workload has 4,950 pairs and 3,030 occupied seconds.
Two ordinary limit workloads exit 1 with no bundle. Resolution exhaustion and an
orphan override exit 2 with incomplete reports, zero occurrences from the affected
family, source fingerprints and explicit diagnostics. None leave staging files.

Reproduce all workload shapes:

```sh
.venv/bin/python scripts/benchmark.py --suite all --output /tmp/calendar-benchmark-v2.json --repeats 3
```

Memory is observed, not capped. Only Linux/Python 3.12 was tested. Synthetic checks
cannot establish real-provider compatibility, full RFC validation, cross-platform
behavior, or completeness of a person's exported calendars. See the bounded
[semantics](../docs/overrides.md) before interpreting results.
